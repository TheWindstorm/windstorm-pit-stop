# Windstorm Pit Stop · DNA Strand Master Plan

**Plan version 1.18 · 2026-11-23 · The Windstorm**

Pit Stop takes three chores off you and your agent: when a Claude Code session refreshes its context, keeping Claude Code current, and keeping Pit Stop itself current, each done at a break in the work.

This document is the blueprint for Windstorm Pit Stop. If you are an agent building or changing any part of it, read Part 0 first and follow it exactly. If you are a person, read Part 1.

## Part 0. Rules for builders

1. Build one gene at a time, from its codons and the invariants in Part 3 only. Do not read the rest of this plan for ideas.
2. Each codon is one claim with one proof. The proof is a test named `test_G<n>_<m>_...` in `tests/`. A codon is built when its test exists and passes in CI today. A codon whose test is missing or failing is not built.
3. A codon whose title ends with "(open)" is planned, not built. Its proof names the test that will prove it.
4. Never change a file to make it differ from its codon. If a codon is wrong, stop, and change this plan first (Appendix A). Then build.
5. Pit Stop uses only the Python 3.10+ standard library, and runs as `python3`, or as `python` where `python3` is not a real interpreter.
6. Every behaviour named here is checked against the code as it is now. The plan describes the code; it is never written from memory.
7. A name in `code` that this plan does not define (a function, a constant, a setting) is defined in the file its codon names; read that file. Names that belong to Claude Code (environment variables, settings, hook events, `CLAUDE_PLUGIN_ROOT`) are defined in Claude Code's documentation at code.claude.com/docs.

## Part 1. The organism on one page

**Philosophy.** Modeled on how life builds: one master plan, read one gene at a time by builders that check their own work. From *God Is a Vibe Coder* by Grant Whitmer.

**The problem.** A Claude Code session that runs for days fills its context. Claude Code then compacts it automatically, often in the middle of a task, and the session carries on with a summary of work it had not finished. Long sessions also stay on the Claude Code release they started with, and a plugin installed from a marketplace other than Anthropic's does not update itself unless someone switches that on.

**The cure.** Pit Stop holds an automatic compaction until the session reaches a break (G1), with the two points fitted to that folder's own history (G2). In fleet mode, a helper on a timer restarts or reloads idle sessions at a break onto the newest Claude Code and the newest Pit Stop (G4, G5, G6, G7), and lists what needs a person (G8). The checkup (G9) shows what is happening on the machine, from local history only.

**What it is not.** It is not a model. Its scripts and hooks call no model, and Pit Stop's own code makes one network request, a version check (INV5). The Claude Code commands it runs in fleet mode, to update Claude Code or plugins, reach their own sources. It works only with Claude Code: the hook, the compaction setting and the updater it uses are Claude Code's own. Other agents are studied, not promised (G17).

**Where it must work.** On macOS, Linux and Windows; with every install method Claude Code has; and in every place a person can ask an agent to add it. The hooks work inside or outside tmux; fleet mode needs tmux, and does nothing without it (G4.29). Where a place cannot support it, Pit Stop will say so (G17, open).

## Part 2. Words used in this plan

- **Session**: one running Claude Code conversation.
- **Folder**: the project directory a session runs in. Settings and history are kept per folder.
- **Refresh, compaction**: Claude Code replacing the conversation so far with a summary. Automatic when the context reaches its window; manual with `/compact`.
- **Break**: the session is waiting for the person, with no tool call running. Its status is `idle`, or `shell` when only background jobs run; for `shell` the helper asks the session first (G4.11).
- **Status**: a session's state as Claude Code's session listing reports it: `idle`, `busy`, `waiting` (a question or permission box) or `shell`.
- **Mid-task**: an automatic refresh that lands while a step is still running.
- **Window**: `CLAUDE_CODE_AUTO_COMPACT_WINDOW`, the context size at which Claude Code starts an automatic compaction. Pit Stop's hook holds it until a break.
- **Idle point**: `CLAUDE_CODE_IDLE_COMPACT_MIN_TOKENS`, the context size above which a quiet session compacts by itself.
- **The two points**: the window and the idle point that Pit Stop fits for each folder.
- **Ceiling**: the context size past which the hook stops holding and lets the compaction through. A configured ceiling is the first found of: env `PIT_STOP_CEILING` (digits only), `ceiling` in the folder profile `~/.claude/pit-stop/folders/<key>.json` (G1.5), `ceiling` in `<cwd>/.claude/pit-stop.json` (G1.4). With none, it is 1.10 times the first hold (G1.3). Every ceiling is then clamped (G1.6).
- **Helper**: `scripts/restart_at_break.py`, run on a timer in fleet mode. Its settings are `~/.claude/pit-stop/restart.json` (defaults in its `CFG`); `--live` acts, and without it the run is a dry run that types and writes nothing (`LIVE` false).
- **config.json**: `~/.claude/pit-stop/config.json`, the person's switches for the hooks and tuning (`auto_tune`, `tune_every_days`, `budget`, `checkpoint_break`, `compact_instructions`, `nudge`, `tune_folders`, `hold_claude_version`, `release_check`).
- **Ask**: the helper's request to a session with background jobs to write its job list to a file (the `okf` path) so it can restart and start them again. The Stop hook passes it on (G11.2).
- **Fleet mode**: the helper running for every session on a machine that uses tmux.
- **Install method**: how Claude Code was installed: native, npm, Homebrew, WinGet, apt, dnf, apk, mise, asdf, nix, or unknown.
- **Generation**: the number in `hooks/generation.json`, raised when a hook change means a running session must reload (G5). Its `hook_files_sha256` is rewritten after every hook change, so each change is looked at (G3.7).
- **Compaction kind**: how `optimize.analyze` labels a `compact_boundary` row: `instant` when `compactMetadata.precomputed` is true; else `mid_task` when the newest earlier prompt, text reply, tool call or tool result was a tool call or tool result; else `idle` when it was a text reply 1800 s or more before; else `prompt`.
- **Open**: planned, not built.
- **Loads the skill** (trigger evals): in one trial, the Skill tool names the stand-in command that carries the description, or the trial's first tool call reads it.

## Part 3. Invariants

**INV1 Never sudo.** No command Pit Stop builds or runs contains `sudo`, `su` or `doas` as a program or argument. Where only an administrator can update, Pit Stop names the command for that person and runs nothing. Proof: `test_INV1_no_command_contains_sudo`.

**INV2 A hook never stops Claude Code by accident.** Every command in `hooks/hooks.json` first checks that its script exists and exits 0 if it does not, and has a timeout of at most 10 seconds. A hook exits with code 2 only on purpose, in two places: the PreCompact hook, to hold a compaction, and the Stop hook, to hand the helper's ask to the session once. Proof: `test_INV2_every_hook_is_guarded_and_capped`.

**INV3 Never types over a person.** Every keystroke the helper sends into a session goes through `type_line()` or `clear_ours()` in `scripts/restart_at_break.py`. `type_line()` types only into an empty input box and presses Enter only when the box holds exactly its text; `clear_ours()` keeps clearing only while what is left is part of that text. Proof: `test_INV3_all_typing_goes_through_type_line_or_clear_ours`.

**INV4 Short notes.** No note the helper types is longer than 560 characters (`NOTE_MAX`), the length past which Claude Code folds typed text into a pasted block. Proof: `test_INV4_note_max_is_560`.

**INV5 Local, except one version check.** The only network request in Pit Stop's own code reads `https://downloads.claude.ai/claude-code-releases/`, read at most every six hours and switched off by `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC`, `DISABLE_UPDATES` or `"release_check": false`. Claude Code commands the helper runs (G6, G7) are Claude Code's own requests. Proof: `test_INV5_one_web_address_only`.

**INV6 No model calls.** No script or hook imports a model SDK or starts `claude -p`. Pit Stop's own cost is the hooks' run time and the text they add. Proof: `test_INV6_no_model_calls`.

**INV7 The owner's no is kept.** Pit Stop never acts against `"hold_claude_version"`, `DISABLE_UPDATES`, `DISABLE_AUTOUPDATER`, an `"autoUpdate": false` the person wrote, a version pin in a project's own file, or a session on a deny list. Proof: `test_INV7_every_no_is_kept`.

**INV8 Every file has a codon.** Every `scripts/*.py`, `hooks/*.py`, `hooks/*.json` and `skills/*/SKILL.md` file appears inside a code span of this plan; every key of `CFG` in `scripts/restart_at_break.py` (the `restart.json` settings) appears in this plan as a whole word; and every path under `scripts/`, `hooks/`, `skills/`, `tests/` or `docs/` that a code span names exists, unless an open codon names it. CI fails otherwise. Proof: `test_INV8_every_file_and_setting_has_a_codon`.

**INV9 Built means proven today.** Every codon not marked "(open)" names a test that exists in `tests/`, no test is marked skip or xfail (one skip is allowed: `pytest.skip("needs a POSIX sh")` on a system without a POSIX shell, which CI's Linux runners have), and CI runs every test on every pull request. Proof: `test_INV9_every_built_codon_has_its_test`.

**INV10 Words about the method.** No Markdown file in the repository says any of these, outside code: `the first to`, `first ever`, `identical to`, `the same algorithm`, `a law of`, `law of nature`, `the ribosome reads the DNA`. Proof: `test_INV10_wording`.

**INV11 Releases come only from checked tags.** A release is a `v*` tag on `main` after every CI check passed. Tags matching `v*` cannot be moved, deleted or force-pushed (a repository rule with no bypass). A release that changes what runs on every machine by itself is tried on one machine for at least a day first; this is a release practice, not code. Proof: by hand.

**INV12 The plan leads.** A change to behaviour starts as a plan change (Appendix A), then is built. Each CHANGELOG entry for a release names the codons it changed. Proof: by hand.

### G1 Refresh at a break
An automatic compaction is held by a PreCompact hook until the session reaches a break (a new prompt, a finished reply, a finished git commit or push late in the hold, or a ceiling), and the summary is told what to keep.

**G1.1 Break or mid-action.** `hooks/precompact_wait_for_break.py`, run as `python3 -I` with the hook JSON (`trigger`, `transcript_path`, `session_id`) on stdin, reads the newest `user`/`assistant` transcript entry. A `tool_use` or `tool_result` there exits 2 with empty stdout; a new prompt or a text reply exits 0. Context is the newest assistant row's `input_tokens + cache_read_input_tokens + cache_creation_input_tokens + output_tokens`; with the env ceiling `PIT_STOP_CEILING=700000` (Part 2, Ceiling) a mid-action 800K context exits 0 and 96K exits 2. Every allowed automatic compaction prints text starting `Pit Stop notes`, adding `middle of a task` only when mid-action. Proof: `test_G1_1_hook_decisions`.

**G1.2 Manual and bad input go ahead.** The hook returns `(0, "")` (exit code, stdout) for `"trigger": "manual"`, for an automatic trigger whose `transcript_path` does not exist, and for stdin `not json`. Proof: `test_G1_2_hook_always_allows_manual_bad_and_missing`.

**G1.3 Default ceiling.** With no configured ceiling, the context at a session's first hold is written to the hold file `~/.claude/pit-stop/holds/<session_id>` (`session_id` kept to letters, digits and `-`), read by later hook runs and removed at the next allow, and the ceiling is 1.10 times it (a constant: no setting changes it; `PIT_STOP_DEFAULT_FLEX`, read until 0.6.1, is not read): first hold at 160K gives 176K, so 170K exits 2 and 180K exits 0. Proof: `test_G1_3_hook_default_flex_ceiling`.

**G1.4 Ceiling from the old project file.** A ceiling in `<cwd>/.claude/pit-stop.json` (`{"ceiling": 300000}`, `cwd` from the hook JSON) is used: a mid-action 310K context exits 0. Proof: `test_G1_4_hook_profile_ceiling`.

**G1.5 Ceiling from the user-level folder profile.** The hook reads `~/.claude/pit-stop/folders/<key>.json` (under `CLAUDE_CONFIG_DIR`), where `<key>` is the absolute `cwd` with every character outside `[A-Za-z0-9]` turned into `-`. With `{"ceiling": 300000}` a mid-action 310K context exits 0 and stdout contains `middle of a task`. Needs: G1.4. Proof: `test_G1_5_hook_reads_the_user_level_folder_profile`.

**G1.6 Configured ceiling clamped.** Every ceiling is cut to `min(1.5 * first_hold, 0.95 * limit)`, where `limit` is `1000000` for a first hold over `200000` and `200000` otherwise. A profile ceiling of `10_000_000` with a first hold at 160K: 189K exits 2, 190K exits 0, and `~/.claude/pit-stop/precompact.log` contains `profile-clamped`. A first hold over 200K: G1.11. Needs: G1.3, G1.4. Proof: `test_G1_6_hook_clamps_a_huge_project_ceiling`.

**G1.7 Keep-list switch and extra note.** `~/.claude/pit-stop/config.json` key `compact_instructions`: `false` makes an allowed break return `(0, "")`; a string is appended so stdout ends `Also: keep the customer list`, under 10000 characters; a config file that is not JSON gives the default text starting `Pit Stop notes`. A manual trigger prints nothing. Proof: `test_G1_7_hook_instructions_can_be_switched_off_or_extended`.

**G1.8 Log rotation.** Before writing its one line per decision, the hook renames a `precompact.log` over 5,000,000 bytes to `precompact.log.1`: after one manual-trigger run, `precompact.log.1` is 5,000,001 bytes and the new `precompact.log` is under 1000 bytes. Proof: `test_G1_8_hook_log_rotates`.

**G1.9 Checkpoint after half the room.** During a hold (first hold 200K, ceiling 220K), a finished `Bash` step whose command runs `git commit` or `git push` (git options like `-C dir`, `-c k=v` allowed) exits 0 once context reaches `first + 0.5 * (ceiling - first)`: 212K exits 0 with `middle of a task`, log's last line has `checkpoint:git-commit`, the hold file (G1.3) is removed, and the command never appears in the log; 205K exits 2. Push wins over commit; `git -C /srv/repo -c user.name=x commit --amend` and `(git push)` count too. Commands `ls -la`, `git log --grep commit`, `git stash push`, `legit commit now`, `git status # commit later` hold. Needs: G1.3. Proof: `test_G1_9_hook_checkpoint_break_after_half_the_room`.

**G1.10 Checkpoint needs a finished step that did not fail.** At 212K the hook exits 2 when: the result has `is_error: true`; another `tool_use` of that answer has no result; the tool is `Edit`; the newest step (later `message.id`) is `npm test`; the commit has no result yet; the commit is in an older answer; `input` is a string. A step is the trailing `tool_result` rows plus the `tool_use` blocks of the one answer (same `message.id`) before them. Needs: G1.9. Proof: `test_G1_10_hook_checkpoint_needs_a_finished_step_that_did_not_fail`.

**G1.11 Checkpoint switch and a wide ceiling.** `"checkpoint_break": false` in `config.json` makes a 212K commit step exit 2; `true` lets it exit 0. With a folder profile ceiling of 300K and a first hold just over 200K (`200015`: the test's usage totals add 15), the G1.6 cut is `min(1.5 * first, 950000)`, so 300K stands: a commit step at 230K exits 2 and at 251K exits 0 (half the room is used at about 250K). Needs: G1.5, G1.6, G1.9. Proof: `test_G1_11_hook_checkpoint_can_be_switched_off_and_respects_a_wide_profile_ceiling`.

**G1.12 Hook registration.** Today `hooks/hooks.json` has exactly the events `PreCompact`, `Stop`, `SessionStart`; each first command starts `F="${CLAUDE_PLUGIN_ROOT}/hooks/<file>"; [ -f "$F" ] || exit 0; P=python3; python3 -I -c pass` for `precompact_wait_for_break.py`, `stop_pit_stop.py`, `session_start.py`, which exist. `PreCompact` has `"matcher": "auto"`. The Stop command run by `sh -c`, with an ask waiting in `~/.claude/pit-stop/asks/s.json`, exits 2 with empty stdout and, on stderr, the ask text of G11.2, which contains `background jobs`. Proof: `test_G1_12_every_hook_command_uses_the_python_probe_and_the_stop_command_passes_exit_2`.

**G1.13 Python fallback in the hook command.** The PreCompact command `F="${CLAUDE_PLUGIN_ROOT}/hooks/precompact_wait_for_break.py"; [ -f "$F" ] || exit 0; P=python3; python3 -I -c pass </dev/null >/dev/null 2>&1 || P=python; exec "$P" -I "$F"`, run by `sh -c` with a `python3` stub that prints a Microsoft Store message and exits 9 first on PATH, and again with a real `python3`: mid-action exits 2 with empty stdout, a break exits 0 with stdout starting `Pit Stop notes`, never the stub's text. Needs: G1.12. Proof: `test_G1_13_hook_command_falls_back_to_python_when_python3_is_a_stub`.

**G1.14 Missing plugin folder lets Claude Code go on.** With `CLAUDE_PLUGIN_ROOT` set to a folder that does not exist, each of the three hook commands run by `sh -c` returns exit 0 and empty stdout. The old command without `[ -f "$F" ] || exit 0` exits 2 there. Needs: G1.12. Proof: `test_G1_14_a_hook_whose_plugin_folder_is_gone_lets_claude_code_go_on`.

**G1.15 Instant summary is not mid-task.** `scripts/optimize.py` `analyze()` counts a `compact_boundary` whose `compactMetadata.precomputed` is true as `instant`, and one without it whose newest earlier prompt, reply, tool call or result was a tool call or result as `mid_task` (Part 2, Compaction kind): for one of each, `compactions_when` gives `(instant, mid_task) == (1, 1)`. Needs: G2.2. Proof: `test_G1_15_a_summary_swapped_in_instantly_is_not_counted_as_mid_task`.

**G1.16 The README says Claude Code asks before the window.** The Window row of the table in `README.md` says Claude Code asks to compact a little before the context reaches the window, gives the one measurement seen (2026-11-22, Claude Code 2.1.330: 108K with a 23K result pending, at a 150K window) as seen once, not promised, and does not say `at once`. Seen 2026-11-22: it said "Above it, Claude Code wants to compact at once". Proof: `test_G1_16_readme_says_claude_code_asks_before_the_window`.

**G1.17 A tool call cut off by a restart is a break (guard).** `hooks/session_start.py` with `"source": "resume"` writes the time to `pit-stop/started/<session_id>`. `hooks/precompact_wait_for_break.py` treats a newest `tool_use` with no `tool_result`, dated before that time, as a break and exits 0; one dated after it still exits 2. ### G2 Refresh point tuned per folder
`/pit-stop optimize` and a daily background tune read a folder's own session history and set its idle point, window and hook ceiling, moving one step at a time and checking each move before the next.

**G2.1 Topic change.** `scripts/optimize.py` `drift_of(paths)` splits the list into chunks of `DRIFT_WINDOW = 30` and returns, for each chunk after the first, `1 - |A & B| / |A | B|` of its set against the one before: 120 paths cycling `/a`, `/b`, `/c` give a non-empty list of zeros; 120 paths with a new folder every 30 give a minimum of 1; 10 paths give `[]`. Proof: `test_G2_1_topic_change_measure`.

**G2.2 Analyze and recommend within bounds.** `analyze(project, days)` reads the `*.jsonl` transcripts in `~/.claude/projects/<project_key>/` (`pitstop_common.transcripts`; several files: G2.5) and counts `system`/`compact_boundary` rows as `compactions`. Three cycles of 20 prompts with `Read` calls peaking at 490K give `compactions == 3`. `recommend(m)`, `m` being what `analyze` returns, takes a 1M limit (max context over 200K) and, with 2 or more compactions and no window set yet (G2.8, G2.10), returns `300000 <= window <= 700000`, `ceiling = max(min(window + 200000, 850000), window)` so `window < ceiling <= 850000`, and `model_effort_suggestions`, a non-empty list of suggestion lines that is never applied. Needs: G2.1. Proof: `test_G2_2_optimizer_recommends_within_bounds`.

**G2.3 Idle point and step limit.** Four cycles of 30 prompt, `Read`, `tool_result` steps give `compactions == 4`, `compactions_when["mid_task"] == 4`, `0 <= topic_change <= 1`. With a 1M limit and no window set, `recommend` gives `100000 <= idle_point <= 300000`, `idle_point <= window - 100000`, `300000 <= window <= 700000`, `window <= ceiling <= 850000` (the G2.2 ceiling). With `max_steps=1` from window 700K and idle 300K: window at least 600K, idle at least 250K. `toward(500000, 300000, 100000, 1) == 400000`; `now` or `max_steps` None returns the target. `max_context=180000` gives `idle_point == 100000`, `window <= 170000`. Needs: G2.2. Proof: `test_G2_3_optimizer_two_points_within_bounds`.

**G2.4 Cold wake-ups.** A prompt more than 3600 s after the previous dated row is a cold wake-up; `analyze` reports `cold_wakes_per_day` over the history's span. Prompts 90 minutes apart (2 cycles of 12) give `cold_wakes_per_day > 3`, and `recommend` adds a `why` line containing `cold wake-ups`. Needs: G2.3. Proof: `test_G2_4_cold_wake_ups_are_counted`.

**G2.5 Usage per day.** `analyze` counts one model call per `message.id` (two rows with one id are one call). One call (minutes of history): `cache_read_per_day` is None, as for any history under a day. Two calls two days apart, each reading 300000 from the cache: `calls_per_day == 1`, `cache_read_per_day == 300000`, `busiest_session_read_per_day == 300000` (the most cache reads per day of any one transcript with a day of history). Twenty more such sessions: `cache_read_per_day == 6300000`, busiest still 300000. Needs: G2.2. Proof: `test_G2_5_usage_per_day_needs_a_day_of_history_and_counts_a_model_call_once`.

**G2.6 Each compaction's re-reads.** For each `compact_boundary` with `compactMetadata.trigger == "auto"`, an integer `preTokens` and a time, `analyze` keeps `[time, preTokens, checks, rereads]` in `compaction_rereads`: checks are file reads in the first 15 tool calls after it, rereads those read in the cycle before. Result `[[t12, 467000, 6, 6], [t13, 366000, 6, 0]]` (manual boundary skipped). `at_point(m, lo, hi, since, until)` returns `(count, checks, rate)`: `(2, 12, 0.5)`; `lo=400000` `(1, 6, 1.0)`; `hi=400000` `(1, 6, 0.0)`; `since=t13` `(1, 6, 0.0)`; `until=t13` `(1, 6, 1.0)`; malformed rows `(0, 0, None)`. Needs: G2.2. Proof: `test_G2_6_analyze_keeps_each_compaction_with_its_time_size_and_re_reads`.

**G2.7 Odd rows do not stop analyze.** A `message.id` that is a list or an object, and a `compactMetadata` that is a string, still give `compactions == 1` and `max_context > 0` from `analyze`. Needs: G2.5. Proof: `test_G2_7_analyze_survives_odd_transcript_rows`.

**G2.8 Thin history keeps the window.** With fewer than 2 compactions, `recommend` keeps `current_window` (950000 stays 950000; 150000 stays 150000 with `idle_point == 100000` and `ceiling >= window`) and, with none set, returns 500000. Needs: G2.3. Proof: `test_G2_8_thin_history_leaves_the_window_where_it_is`.

**G2.9 Budget caps a heavy folder.** `recommend(m, budget=...)`, default `budget` from `config.json` (absent or unknown: `balanced`), sets `usage_class` by `busiest_session_read_per_day` as `light < 100M <= heavy < 250M <= very heavy`. `roomy`: no cap, `usage_class` None. `balanced`: light (50M) unchanged; heavy 500K, class `heavy`; very heavy 400K, `est_read_saving >= 0.3`, `why` naming `very heavy` and `roughly`. `economy`: light 400K, very heavy 300K. Re-reads `>= 0.30` add 100K to the cap. A cap never raises (300K, 400K stay); `max_steps=1` from 600K gives 500K. At `max_context` `150000` with window `70000` economy keeps it unless re-reads `>= 0.30`; balanced raises it. Needs: G2.3. Proof: `test_G2_9_budget_caps_the_window_of_a_folder_that_reads_a_lot`.

**G2.10 Budget edges and read saving.** From 1M with `max_steps=1`, `balanced` and `economy` never exceed `roomy`. Very heavy at 250K stays (`why` has `stays at 250K`); economy at 200K stays with one `stays at` line. ### G19 A proof is a test that ran

A codon or a PROMISES row counts as proven only by a test the runner collected and passed in this run, never by a name found in a file.

**G19.1 Counted from the run.** `tests/conftest.py` records every test that PASSED in the session. On a whole-suite run, it fails the run when a built codon's Proof or a PROMISES row's `test` failed or was not collected, at any version; one skipped on a condition of the machine fails it only in CI (G19.3). A whole-suite run is one that collected every top-level `test_*` function in `tests/test_*.py` and deselected none; any other run prints `partial run: rows and codons not checked` and checks nothing. There is no switch. Proof: `test_G19_1_a_built_proof_that_did_not_pass_fails_the_whole_run`.

**G19.2 One name, one test.** No `tests/test_*.py` file defines the same top-level name twice, because a later definition hides the earlier test, which then never runs. Seen 2026-11-22: a test hidden this way still satisfied every name check. Proof: `test_G19_2_no_test_file_defines_a_name_twice`.

**G19.3 A skip says why and is not a pass.** A skipped test never counts as passed. The summary lists it as `not run here: <test> (<reason>)`. Outside CI, a skip on a condition of the machine, with its reason, does not fail the run; in CI (the environment variable `CI` is `true`), a built proof that did not pass fails it. A skip with no reason, or on no condition of the machine, fails every run. Proof: `test_G19_3_a_skip_is_listed_and_never_counts_as_passed`.

**G19.4 The plan check runs in CI.** CI runs `tests/test_strand.py` on every push and pull request. Its checks, written in this repository: version line; genes under Genes; codon form, heading, numbering; invariant Proofs; named ids exist; no loop in what codons need; genes in Milestones; ASSUMES: on open questions; the changelog's newest Plan entry; the 80-word cap. A built codon's test must pass (G19.1); an open one only names it. Vague words are the lane's hand check, not CI's. Proof: `test_G19_4_ci_runs_the_plan_check`.

**G19.5 The suite never uses the home of the account running it.** `tests/conftest.py` gives the run its own home, Claude Code folder and tmux folder, puts failing stubs for tmux, claude, crontab, systemctl, loginctl and launchctl first on PATH, and fails a test that reaches the real home (less the checkout and Python's libraries) or tmux folder, starts a child with the real HOME, none, or a PATH reaching those programs, or runs one. Seen 2026-11-24. Proof: `test_G19_5_the_suite_never_uses_the_home_of_the_account_running_it`.

**G19.6 Undo in the suite reaches only its made home.** A test calls setup's undo with nothing moved, so its config.json step (with no record it turns daily tuning off) acts on the made home's file, and fails if the real config.json's or settings.json's time or size moves; pointed at a stand-in, the same undo is seen to move it. Seen 2026-11-24 03:32:14Z, before G19.5: a test's undo turned tuning and self-update off in an account's real files. Proof: `test_G19_6_undo_in_the_suite_reaches_only_its_made_home`.

**G19.7 The suite's lists do not lean on where the machine keeps its programs.** The tests that count the open-folder lines run with the Python program where the test put it; one test runs them from a Python in a folder left open and sees them pass. Seen 2026-11-24 on a CI runner: its Python's folder was open, and the check rightly named it. Proof: `test_G19_7_the_suites_lists_do_not_lean_on_the_machines_python`.

**G19.8 A row that still owes part is not proven (open).** A row may carry proof_owed, what is still to be seen on a real machine. The gate after a release counts a shipped row proven only when its proven line is not empty and proof_owed holds nothing, and names what is owed; words in the line decide nothing. One function decides, called by the gate and its test. Seen 2026-11-24: family rule 32. Proof: `test_G19_8_a_row_that_still_owes_part_is_not_proven`.

**G19.9 CI runs the suite on a Mac (open).** Every release head is tested on GitHub's macOS runner with the python3 of Apple's developer tools; a proof of one platform is named with its reason in one list the gate reads, never skipped in bulk. Proof: `test_G19_9_ci_runs_the_suite_on_a_mac`.

**G19.10 The Python floor is the one CI runs, checked first (open).** The README, the plan and CI's lowest leg name one floor; each program checks it as its first act and below it says so and changes nothing. Proof: `test_G19_10_the_python_floor_is_the_one_ci_runs_checked_first`.

**G19.11 A test changes a mode only on the folder it made (open).** A child a test starts changes a mode only after reading that the folder is under the test's made folder; otherwise it changes nothing and the test is reported not run here, with the reason. Proof: `test_G19_11_a_test_changes_a_mode_only_on_the_folder_it_made`.

## Appendix A. Changing this plan

1. A plan change is its own pull request, titled `Plan: <what changes>`, touching only this file and `CHANGELOG.md`.
2. It says which codons change and why.
3. Codons are never renumbered. A removed codon stays in place as `**G<n>.<m> Removed in plan X.Y:** <reason>`.
4. 1.x adds or clarifies genes and codons. A change to an invariant or to Part 0 is 2.0.
5. Public wording in this file is checked against the code by its author before it merges, and reviewed by the project's legal reviewer before launch.
